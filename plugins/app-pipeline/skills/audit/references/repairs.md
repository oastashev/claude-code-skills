# Исправления и повторная проверка

Сначала установи владельца нормативного источника. Для обычного самостоятельного документа допустима прямая авторизованная правка с сохранением предыдущей редакции. Для Markdown, опубликованного assemble, источник истины — snapshot текущей ревизии, не Markdown.

## Комплект assemble

1. Прочитай CURRENT, manifest, snapshot, policy, review и актуальные документы. Проверь status доступным specctl; при DOCS-PENDING используй штатное восстановление assemble до изменения требований. Не исправляй immutable revisions, CURRENT, sources или approvals вручную.
2. Зафиксируй находки со стабильными ID, цитатами, контрпримером и условием закрытия. Сам запрос исправить дефекты разрешает эту работу, но не подменяет утверждение ещё не показанной редакции.
3. Выполни рабочий цикл assemble change на текущей стадии: новый пакет от CURRENT, изменения entities/edges и при необходимости композиции documents, impact и полный критический проход. Импортируй отчёт аудита как источник; свяжи находки пакета с исходными F-ID. Изменение бизнес-решения требует реального решения пользователя; техническое устранение доказанного расхождения — в авторизованном scope.
4. Прими только прошедший проверки пакет. Для финального результата нужен stage-review. Получи или используй уже данное явное утверждение именно этой новой редакции; approve регистрирует ответ, не создаёт его. Старая ревизия остаётся историей.
5. Выполни audit recheck по новому CURRENT с новым manifest и сравнением всех прежних открытых находок. Правка не равна закрытию: проверь условие закрытия и обратное влияние. Старый аудит и kickoff остаются привязаны к старым хешам; нужны новый аудит и kickoff revise, а не переписывание baseline прежнего плана.

Если assemble недоступен, подготовь исправленный кандидат/предложение и укажи, что публикация блокирована. Не обходи источник истины правкой generated Markdown.

## Если Markdown уже изменён вручную

Сохрани фактические изменённые байты и diff как входящий материал. Проверь исходную ревизию и отсутствие постороннего писателя. Для запуска пакета восстанови опубликованную копию из проверенного CURRENT только после сохранения правок и проверки, что файл с тех пор не изменился. Перенеси смысл сохранённой правки в новый пакет; восстановление копии само по себе не исправляет находку. При неоднозначном состоянии остановись, не угадывай победившую версию.

## Контроль завершения

- Документы, snapshot, RTM, review и CURRENT относятся к одной принятой ревизии.
- Статус approved новой редакции подтверждён фактическим ответом, либо результат явно оставлен accepted без разрешения реализации.
- Recheck сохраняет прежние F-ID и объясняет каждый resolved/retracted/open.
- Старый kickoff не используется для изменённой спецификации; его актуальность перепроверяется по хешам.
