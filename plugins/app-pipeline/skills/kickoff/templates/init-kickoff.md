# Init kickoff

Подготовь существующий репозиторий к реализации утверждённого плана. Не создавай changes, design/tasks и состояние выполнения, не реализуй приложение и не запускай следующий этап автоматически.

1. Найди корень Git, прочитай docs/kickoff/plan.json, baseline.json, review.json, approval.json и docs/07-kickoff.md. Запусти `python docs/kickoff/tools/planctl.py check --root . --plan docs/kickoff/plan.json --execution`. Ошибка, UNKNOWN, неподтверждённая редакция или изменённый baseline блокируют инициализацию. Проверь фактическое происхождение approval и полноту baseline, не только JSON.
2. Зафиксируй git status, ветку и хеши затрагиваемых файлов. Не присваивай чужие изменения. Существующие AGENTS.md/конфигурацию прочитай; добавляй только согласованные правила. При конфликте покажи конкретное изменение. Не используй git add -A.
3. OpenSpec — адаптер плана. Проверь установленную версию, локальные --help, схему и инструкции CLI. Не устанавливай @latest автоматически и не используй неподтверждённые flags. Нет CLI/совместимости — блокер с необходимым действием. Не ослабляй validation.
4. Инициализируй OpenSpec и только реально используемые пользователем интеграции агентов. Сохрани существующие specs и changes; различай текущее поведение и будущие delta, не объявляй любой проект greenfield.
5. В AGENTS.md отрази фактическую архитектуру, команды и правила источников. Не добавляй обязательные слои, язык требований, CI или линтер вопреки спецификации. Неизвестная команда — условие, а не выдумка.
6. Запиши docs/kickoff/adapter.json: plan_hash, версия CLI, схема, фактические команды validate/archive. Секреты не сохраняй.
7. Проверь результат: validation CLI на текущем состоянии, соответствие AGENTS.md реальным путям и командам. Коммить только известные созданные/изменённые пути, не пушь. Повторный запуск сверяет plan_hash в adapter.json, дополняет отсутствующее и не перезаписывает существующее без сравнения.

Перенос проекта должен включать все пути baseline, включая outputs/audit, полный docs/specification и planctl.py. Старый STATUS.md не является источником разрешения.

Прерывание с неопознанными изменениями → остановка и описание восстановления; не удаляй их ради повторного запуска. Итог: готовность репозитория, adapter.json, ограничения и следующий шаг — создание changes по плану скилом scaffold (`/scaffold` плагина app-pipeline). Не объявляй проверенным поведение ещё не созданного приложения.
