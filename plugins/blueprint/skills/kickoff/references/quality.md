# Качество плана

После каждого среза и для полного плана:
| Критерий | Условие |
|---|---|
| baseline | CURRENT/ревизия/политика/approval совпадают; аудит покрывает те же входы и scope; mandatory gates удовлетворены |
| scope | Включения необходимы для MVP; отложенное не обещано; обязательные ограничения сохранены |
| atomicity | Срез имеет связный результат и границу; его модули и контракты достаточны для результата и выполнимы с указанными предпосылками |
| completeness | Все active obligations классифицированы, включённые реализуются и проверяются; пользовательский путь завершается |
| consistency | Нет циклов, несовместимых контрактов, нарушения зависимостей и условий |
| verifiability | Есть различающие сценарии, coverage по срезам и методы; локальные проверки выполнимы сразу, интеграционные назначены после необходимых зависимостей; объединение покрывает всю гарантию |
| feasibility | Среда/доступы/размер реалистичны; неизвестные оценки не превращены в точные сроки |
| contracts | Сохранены API, данные, ошибки, единицы, лимиты, безопасность и восстановление |
| traceability | Основания подтверждают необходимость; owners/applies_to/checks соответствуют смыслу |
| assumptions | У условий есть владельцы, сроки и evidence; блокеры планирования не отложены |

Ошибки продукта/архитектуры исправляются через specify и новый audit, ошибки раскладки — в kickoff.
Наличие ID и OpenSpec validate не заменяют смысловое ревью. Необязательный UNKNOWN аудита не превращается в PASS реализации.

Анализ параллелизма обязателен даже при последовательном execution; следуй parallelism.md и сопоставляй варианты с реальными ограничениями. Проверяй API, данные, схемы, миграции, fixtures, пакеты, внешние ресурсы и области записи. Непересечение путей не доказывает независимость. Каждая пара выбранной волны требует independent с основанием; unknown означает последовательность. Общие файлы не становятся безопасными от названия «очередь»: разведи по волнам. Не делай прогноз экономии из S/M/L без исходных допущений и не называй жадную раскладку оптимальной.

Изменившийся вход → STALE и повторное ревью. FAIL/UNKNOWN обязательного критерия → draft. READY без approval → показать редакцию пользователю. Открытое условие блокирует соответствующую операцию, независимая работа допустима.
